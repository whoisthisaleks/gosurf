# Go Surf Bali — Инструкции для AI-разработчика

## 1. О проекте

Go Surf Bali — это продукт для серферов на Бали.

Главная задача продукта:

Помочь серферу быстро ответить на вопрос:

"Куда ехать серфить сегодня и почему?"

Текущая версия — Telegram-бот.

Будущая версия:
- Telegram Mini App;
- персональные рекомендации;
- серф-дашборд;
- интеллектуальный помощник для выбора спота.


---

# 2. Философия продукта

Главный принцип:

Не показывать серферу слишком много данных.

Пользователю не нужен ещё один сложный прогноз.

Пользователю нужно решение:

"Сегодня лучше ехать в Canggu с 10:00 до 13:00, потому что направление свэлла, период и тайд подходят лучше всего."


Задача продукта:

Превратить сложные океанские данные в простую рекомендацию.


---

# 3. Текущий технологический стек

Backend:

- Python


Telegram:

- aiogram 3
- Telegram Bot API


Разработка:

- VS Code
- Codex Agent


Внешние API:


## Stormglass API

Используется для:

- высоты волны;
- периода свэлла;
- направления свэлла.


## Tide API

Будет использоваться для:

- приливов;
- отливов;
- текущего уровня воды;
- лучших временных окон для каждого спота.


Будущее:

- Telegram Mini App.


---

# 4. Архитектура проекта

Проект должен оставаться модульным.


---

# bot.py

Отвечает только за Telegram-интерфейс.


Отвечает за:

- команды пользователя;
- кнопки;
- callback;
- отображение результата;
- форматирование сообщений.


НЕ должен содержать:

- работу с API;
- расчёты серф-условий;
- бизнес-логику;
- правила выбора спота.


Правильный поток:

Пользователь

↓

bot.py

↓

получение данных

↓

decision_engine.py

↓

ответ пользователю


---

# weather.py

Отвечает за получение данных океана.


Источник:

Stormglass API.


Основные данные:

wave_height
period
swell_direction


Пример структуры:

```python
{
    "wave_height": 1.2,
    "period": 14,
    "swell_direction": "SW"
}
Не добавлять лишние данные без необходимости.
Не использовать без причины:
ветер;
дополнительные погодные параметры;
данные, которые не влияют на решение.
Главная цель:
Получить только те данные, которые помогают выбрать спот.
tide.py
Отвечает за данные приливов и отливов.
Должен предоставлять:
текущий тайд;
следующий high tide;
следующий low tide;
оптимальное окно для каждого спота.
Пример:
{
    "current": "mid",
    "next_high": "14:30",
    "next_low": "08:20"
}
spots.py
База знаний о серф-спотах.
Содержит:
название спота;
координаты;
уровень сложности;
подходящие направления свэлла;
предпочтительные тайды;
локальные особенности.
Основные споты:
Canggu
Kuta
Uluwatu
Medewi
Этот файл является базой локальных серф-знаний.
decision_engine.py
Главный модуль принятия решений.
Отвечает за:
анализ условий;
сравнение спотов;
расчёт рейтинга;
выбор лучшего места;
объяснение причины.
Использует:
уровень серфера;
wave height;
period;
swell direction;
tide.
НЕ должен:
работать с Telegram;
напрямую обращаться к API.
Архитектура:
API данные

↓

Decision Engine

↓

Recommendation

↓

Telegram Bot

6. Правила разработки
Перед изменением любого кода:
Всегда:
Изучить текущий код.
Понять зависимости между файлами.
Определить какие файлы будут изменены.
Объяснить план изменений.
Только после этого менять код.
Не делать:
полные переписывания без необходимости;
изменения архитектуры без объяснения.
7. Правила качества кода
Главные приоритеты:
Стабильность.
Простота.
Понятная архитектура.
Быстрый MVP.
Избегать:
лишней сложности;
переархитектуры;
больших файлов;
дублирования логики.
Каждый модуль должен выполнять свою задачу.
8. Правила работы с данными
Нельзя менять структуру данных без проверки зависимостей.
Например:
Было:
height
Стало:
wave_height
Перед изменением необходимо проверить:
bot.py
weather.py
decision_engine.py
тесты
Любое изменение общей структуры данных должно сопровождаться проверкой всех использующих её файлов.
9. Правила работы с API
Все внешние API должны иметь:
обработку ошибок;
fallback;
логирование;
кеширование.
Нельзя:
делать бесконечные запросы;
игнорировать лимиты API;
падать при отсутствии данных.
Плохо:
data["hours"][0]
без проверки существования данных.
Хорошо:
if "hours" not in data:
    handle_error()
